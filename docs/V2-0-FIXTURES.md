# V2-0 Fixtures Specification — Deterministic Test Media and Verification

- Baseline: commit `24df92b2084055b3bea05ad46eccd00c1f09a1eb` (`main`).
- Scope: This document defines the deterministic test fixture classes, generation commands, expected probe properties, failure modes, toolchain assumptions, manifest schema, and baseline verification tooling for PlayoutTranscode V2-0.

---

## 1. Frozen V1 Invariants & Behavior

The following observable V1 behaviors are frozen and MUST NOT be changed in V2-0:

1. **25/1 CFR Forced Output**: All encoded output generated by PlayoutTranscode profiles (Profile A, Profile B, Profile C) is forced to `25/1` Constant Frame Rate (CFR) (`src/profiles.rs:4-5`). Source rational FPS is probed and snapped to broadcast rationals (`src/probe.rs:286-301`), but the encoder normalizes frame output to 25 fps via `-vf fps=25/1 -r 25/1 -fps_mode cfr`.
2. **`mezzanine_ok` vs `status="ready"` Warning Semantics**: In V1, post-encode validation checks (such as `fps_mismatch`, `audio_sample_rate_not_48k`, `closed_gop_violation`, `missing_faststart`) append warning strings to `warnings` and set `mezzanine_ok = false`, but the asset is still published with `status="ready"` (`src/processor.rs:259-307`). Hard failures that route to `status="error"` are restricted to probe failure, encode process error, missing output file, zero-byte file, or duration mismatch beyond tolerance.
3. **PlayOutVue Wire Contract Backward Compatibility**: PlayOutVue downstream client expects exact JSON field names (`playoutvue_id`, `current_path`, `duration_ms`, `trim_in_ms`, `trim_out_ms`, `fps_num`, `fps_den`, `mezzanine_ok`, `warnings`, `keyframe_offsets`). V2-0 preserves every field and primitive definition without alteration.

## 2. Toolchain Assumptions & Error Handling

- **Tooling Requirements**: Generation and baseline verification require `ffmpeg` and `ffprobe` (version 6.0+ or 7.x recommended).
- **Resolution Path**: `scripts/generate-fixtures.ps1` and `scripts/verify-baseline.ps1` search for executables in the following order:
  1. System `PATH`
  2. Local directory `$PSScriptRoot/../bin/ffmpeg.exe` (or `ffprobe.exe`)
  3. Cargo target directory `$PSScriptRoot/../target/debug/bin/ffmpeg.exe`
- **Explicit Failure Policy**: If `ffmpeg` or `ffprobe` is not found, both PowerShell scripts **MUST fail clearly** with a descriptive error message and exit code `1`. They must **NEVER** silently succeed, skip verification, or generate dummy 0-byte placeholders.

## 3. Fixture Classes & Generation Commands

All fixtures are generated using FFmpeg synthetic filter sources (`lavfi`), ensuring 100% deterministic binary creation without external assets.

| Class | Filename | Specifications | Purpose |
|---|---|---|---|
| **1. Video Only** | `video_only.mp4` | 1920x1080, 25fps, 5.0s, H.264 high, yuv420p, **no audio** | Test video-only ingest and optional audio mapping (`0:a:0?`) |
| **2. Audio Only** | `audio_only.mp3` | MP3, 44.1 kHz, 2 ch stereo, 5.0s, **no video** | Test audio-only source handling |
| **3. Video + Stereo** | `video_stereo.mp4` | 1920x1080, 25fps, 5.0s, H.264, AAC 48 kHz stereo | Standard HD progressive ingest candidate (Profile A) |
| **4. Multichannel** | `multichannel.mkv` | 1920x1080, 25fps, 5.0s, H.264, 6-ch (5.1) PCM 48 kHz | Test multichannel audio downmix to 48 kHz stereo |
| **5. VFR Source** | `vfr_source.mp4` | 1920x1080, variable fps (24-30 fps timestamps), 5.0s, AAC 48 kHz | Test VFR probe detection and 25/1 CFR normalization |
| **6. Interlaced TFF** | `interlaced_tff.mp4` | 1920x1080, 25fps, 5.0s, H.264 interlaced (top field first), AAC 48 kHz | Test Profile B selection and interlaced preservation |
| **7. Corrupt/Truncated** | `corrupt_truncated.mp4` | Truncated H.264 MP4 container (first 64 KB of valid MP4) | Test error detection, probe failure, and cleanup |
| **8. Compliant Mezzanine** | `mezzanine_compliant.mp4` | 1920x1080, 25fps CFR, closed GOP 50, faststart, AAC 48 kHz stereo | Test passthrough validation and `mezzanine_ok=true` |

### Deterministic Generation Commands

```powershell
# 1. Video Only (5.0s, 1920x1080, 25fps)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=25 -t 5.0 -c:v libx264 -pix_fmt yuv420p video_only.mp4

# 2. Audio Only (5.0s, 44.1kHz stereo)
ffmpeg -y -f lavfi -i sine=frequency=440:sample_rate=44100 -t 5.0 -c:a libmp3lame -b:a 192k audio_only.mp3

# 3. Video + Stereo Audio (5.0s, 1920x1080, 25fps, AAC 48kHz)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=25 -f lavfi -i sine=frequency=1000:sample_rate=48000 -t 5.0 -c:v libx264 -pix_fmt yuv420p -c:a aac -b:a 320k video_stereo.mp4

# 4. Multichannel (5.0s, 6-channel 5.1 PCM audio)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=25 -f lavfi -i sine=frequency=440:sample_rate=48000 -t 5.0 -c:v libx264 -pix_fmt yuv420p -filter_complex "[1:a]pan=5.1|c0=c0|c1=c0|c2=c0|c3=c0|c4=c0|c5=c0[aout]" -map 0:v -map "[aout]" -c:a pcm_s16le multichannel.mkv

# 5. VFR Source (5.0s, variable timestamps)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=30 -f lavfi -i sine=frequency=440:sample_rate=48000 -t 5.0 -vf "select='not(mod(n\,3))',setpts=N/(24*TB)" -c:v libx264 -pix_fmt yuv420p -c:a aac vfr_source.mp4

# 6. Interlaced TFF (5.0s, 1080i50)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=25 -f lavfi -i sine=frequency=440:sample_rate=48000 -t 5.0 -c:v libx264 -flags +ilme+ildct -top 1 -pix_fmt yuv420p -c:a aac interlaced_tff.mp4

# 7. Corrupt / Truncated File
# (Generated by creating a short 1s MP4 and truncating to 32 KB)

# 8. Compliant Mezzanine (5.0s, closed GOP 50, faststart)
ffmpeg -y -f lavfi -i testsrc2=size=1920x1080:rate=25 -f lavfi -i sine=frequency=1000:sample_rate=48000 -t 5.0 -c:v libx264 -preset medium -crf 24 -profile:v high -level 4.2 -pix_fmt yuv420p -g 50 -keyint_min 50 -sc_threshold 0 -x264-params open-gop=0:keyint=50:min-keyint=50:scenecut=0 -movflags +faststart -c:a aac -b:a 320k -ar 48000 -ac 2 mezzanine_compliant.mp4
```

## 6. Manifest Hash Policy (Toolchain-Specific & Informational)

Binary FFmpeg outputs vary across OS platforms, FFmpeg versions, and CPU SIMD optimizations. Therefore:
- Source SHA-256 hashes in `manifest.json` are **informational and toolchain-specific**.
- Baseline verification (`verify-baseline.ps1`) validates **semantic probe properties** (duration, resolution, frame rate rationals, codec, channel count, sample rate) as primary assertions.
- Output file SHA-256 hashes are logged during verification for auditability but do not fail verification if probe invariants pass.
